# 線上算命系統 PRD (Product Requirements Document)

## 1. 專案概述

### 背景與動機
現代人生活忙碌，遇到升學、就業或感情上的迷惘時，不一定有時間或精力親自到廟宇求籤或找尋算命師。為了滿足這方面的需求，我們期望建立一個「線上算命系統」，讓使用者可以不受時間與地點限制，透過網路輕鬆進行線上抽籤、占卜與算命，尋求心靈上的指引與寄託。

### 目標用戶
- 對運途、緣份、事業或健康有疑問，需要尋求心靈寄託或指引的普羅大眾（如學生、上班族等）。
- 喜歡求籤、占卜，但無法實地造訪廟宇的使用者。

### 核心價值主張
- **便利性**：隨時隨地不受限地進行心靈指引與解答。
- **紀錄保存**：為使用者長期保存算命與抽籤結果，方便日後對照回顧。
- **回饋機制**：提供添香油錢功能，讓使用者可以進行捐獻與還願。

---

## 2. 功能需求

### 主要功能與使用者故事

#### 1. 線上抽籤與占卜
* **使用者故事**：作為一名「迷惘的使用者」，我希望「能在線上進行完整的求籤或占卜流程（例如擬真的擲筊、抽籤）」，以便「獲得神明或占卜結果的指引」。

#### 2. 詳細的籤詩/占卜解析
* **使用者故事**：作為一名「獲得籤詩的使用者」，我希望「系統能提供白話文的詳細解籤說明（包含事業、感情、健康等方面的吉凶）」，以便「我能正確理解結果的含義」。

#### 3. 儲存算命結果 (歷史紀錄)
* **使用者故事**：作為一名「註冊會員」，我希望「系統能自動儲存我過去的算命或抽籤紀錄」，以便「我日後可以隨時回顧先前的指引並驗證是否靈驗」。

#### 4. 捐贈（添香油錢）功能
* **使用者故事**：作為一名「想表達感謝的使用者」，我希望「能透過系統選擇金額進行線上『添香油錢』的捐獻」，以便「支持系統營運或還願」。

#### 5. 會員註冊與登入
* **使用者故事**：作為一名「想要長期使用的訪客」，我希望「能註冊個人專屬帳號並登入」，以便「保障我的隱私並能順利使用歷史紀錄儲存等專屬功能」。

## 3. 非功能需求

### 技術限制
- 原型開發預計使用 **Flask + Jinja2 + SQLite** 作為前後端與資料庫架構。
- 專案程式碼需遵循易於維護的 MVC 架構或 Blueprint 模組化設計。

### 效能與安全考量
- **安全性**：會員密碼需經過加密（如 bcrypt）後儲存至資料庫；避免 SQL Injection 攻擊；線上捐獻功能若日後串接第三方金流，需確保交易安全與憑證正確。
- **響應式設計**：由於使用者多半使用手機，前端需注重 RWD（響應式網頁設計），保證在行動裝置上流暢操作。
- **效能**：資料庫設計應具備索引，幫助後續查詢歷史紀錄時有更好的讀取速度。

## 4. MVP 範圍 (Minimum Viable Product)

### Must Have (必要功能 - 第一階段上線)
- 基礎的線上抽籤/占卜功能（流程：點擊 -> 取得隨機結果）。
- 顯示抽中籤詩對應的文字解籤說明。
- 基礎的會員系統（註冊/登入）。
- 歷史紀錄儲存（與使用者綁定）。

### Should Have (重要功能 - 第二階段)
- 線上「添香油錢」功能（可用簡單的表單或模擬金流串接）。
- 較為擬真的抽籤體驗（加入動畫：搖籤筒、擲筊機率計算等）。
- 使用者個人首頁與歷程總覽。

### Nice to Have (加分功能 - 未來展望)
- 其他算命種類擴充（如紫微斗數、塔羅牌、生肖運勢）。
- 每日運勢推播或籤詩提醒功能。
